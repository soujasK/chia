I have investigated and fixed the issue.

### Root Cause
The `ExpandWhens` pass walks the tree using a `WhenOpVisitor`, modifying verification assertions inside `when` blocks to be predicated on the `when` condition. To avoid duplicating logical `and` / `implication` operations for the condition, the visitor maintains caches (`createdLTLAndOps`, `createdLTLImplicationOps`, etc.). 

When it encounters a `LayerBlockOp`, it recursively calls `process(Block &block)` on the body using the *same cache state*. It then caches operations instantiated *inside* the `LayerBlockOp`. However, these operations are local to the layer block's region and **do not dominate** subsequent operations in the outer `when` block or in sibling `LayerBlockOp` regions. The issue occurred because a second layer block was reusing a cached value that was generated and scoped exclusively within the first layer block, causing the dominance verifier error. 

### Fix
I modified `WhenOpVisitor::visitStmt(LayerBlockOp)` in `lib/Dialect/FIRRTL/Transforms/ExpandWhens.cpp` to correctly save and restore the caches around processing the `LayerBlockOp` body. Since a layer block does not own the operations inside it after we exit, this ensures that no locally created operation leaks into the shared cache for subsequent statements, preventing the dominance error.
